# Консольный режим и плеер

[English](../console.md) · **Русский**

Программа на uison может работать без окна. В консольном режиме она пишет свои кадры в stdout и читает события из stdin, по одному JSON-сообщению в строке. **Плеер** (`uison-player`) запускает программу так и показывает её: на одной вкладке — экран программы, на другой — все сообщения в обе стороны. Это задел для программы на одной машине и окна на другой; пока всё на одной машине.

```sh
cargo build --release -p disk-usage -p uison-player
target/release/uison-player target/release/disk-usage --console ~/Documents
```

## Как включить в программе

Когда работать в консольном режиме, решает программа. Обычно — по ключу командной строки:

```rust
fn main() {
    let console = std::env::args().any(|a| a == "--console");
    if console {
        uison::run_console(app(), "My app"); // без окна: кадры наружу, события внутрь
    }
    uison::run(app(), "My app");
}
```

`run_console` есть на macOS, Linux и Windows. Он работает с любым приложением: экраном (`Ui`) или своим кадром (`App`). Текст программа по-прежнему меряет своими шрифтами. Пока она на той же машине, что и плеер, картинка совпадает с обычным окном.

Случайный вывод программы поток не ломает: на macOS и Linux stdout отдан протоколу, а случайный `println!` уходит в stderr. Плеер показывает stderr в журнале.

## Сообщения

От программы:

```js
{"uison":0,"title":"Disk Usage"}                    // первое
{"frame":{"size":[1280,840],"background":"#24252A","items":[…]}}   // кадр целиком после каждого изменения
{"host":"copy","text":"/Users/me/file"}             // буфер обмена — у плеера
{"host":"open","url":"https://…"}                   // ссылка
{"host":"paste"}                                    // пришли содержимое буфера
```

Кадр — обычный [кадр примитивов](../c/lessons/09-frame.md), строгим JSON в одну строку.

Программе — события в [JSON-форме](screens/events.md), по одному в строке:

```js
{"type":"resize","w":1280,"h":796}                  // размер области программы
{"type":"move","x":412.5,"y":230}  {"type":"down","x":412.5,"y":230,"button":"left"}  {"type":"up",…}
{"type":"key","code":"char","text":"a","shift":false,"ctrl":false,"alt":false,"cmd":false}
{"type":"paste","text":"…"}                         // ответ на {"host":"paste"}
{"action":"rescan"}  {"data":{"form.query":"jpg"}}  // сообщения экрану
```

Таймеры, анимация и фоновые потоки работают внутри программы. Программа выходит, когда stdin закрыт.

Управлять программой можно и без плеера:

```sh
printf '%s\n' '{"type":"resize","w":900,"h":600}' '{"action":"about"}' | target/release/disk-usage --console | cut -c1-120
```

## Плеер

`uison-player [<программа> [аргументы…]]`

- Без программы плеер открывает **стартовый экран**: введите командную строку (кавычки объединяют слова, `~` — домашняя папка) или выберите одну из программ, найденных рядом с плеером, или команду этой сессии. **Stop** завершает программу и возвращает сюда; так же — если программа завершилась сама.
- **App** показывает кадры программы. Мышь над ними и клавиши уходят в программу; нажатие, начатое там, держит мышь до отпускания. Программа получает размер области (`resize`) и тему системы.
- **JSON** — список сообщений: направление, время, вид, размер, начало текста. По щелчку сообщение целиком показывается справа. Кадры и движения мыши по умолчанию скрыты, у них свои переключатели. Поле внизу отправляет программе свою строку, например `{"action":"rescan"}`.
- В строке состояния — сообщения и килобайты в обе стороны, кадры в секунду и задержка от мыши или клавиши до следующего кадра.

## Через SSH

`uison-ssh-player` запускает программу на сервере и показывает её здесь. На сервере нужен только `sshd`. На стартовом экране три шага:

1. **Подключиться:** хост, порт, пользователь; файл ключа (и его пароль, если есть) или пароль. На телефоне нет `~/.ssh`: **Choose key…** открывает системный выбор файла («Файлы», Drive) и хранит копию выбранного ключа в папке приложения, доступной только ему, — ключ не проходит через буфер обмена; **New key** создаёт ключ этого устройства и показывает строку для `~/.ssh/authorized_keys` на сервере. Ключ нового сервера запоминается, его отпечаток показывается на экране; сменившийся ключ — отказ. Плеер проверяет `~/.ssh/known_hosts` и ведёт свой список в `~/.config/uison/known_hosts`.
2. **Загрузить** (по желанию): файл с этого компьютера уходит по пути на сервере, по умолчанию `~/uison/<имя>`. Папка создаётся, файл становится исполняемым.
3. **Запустить:** путь на сервере и аргументы; `--console` добавляется, если не снять флажок.

```sh
cargo run --release -p uison-ssh-player -- me@server.example -i ~/.ssh/id_ed25519
```

SSH-библиотека — только в этом плеере: сама программа по-прежнему знает только stdin и stdout. Соединение остаётся открытым между запусками, а **Stop** завершает программу, но не соединение.

Плеер есть и отдельным репозиторием — [uisonlab/uison-ssh-player](https://github.com/uisonlab/uison-ssh-player), он собирается с `uison-player` из crates.io; копия здесь остаётся примером плеера со своим каналом.

## Цена

Замеры на Mac (M-серия), Disk Usage на `/System/Library/Frameworks`:

| | |
|---|---|
| кадр с диаграммой | ~125 КБ JSON |
| программе на событие наведения | 1,7 мс: приложение 1,0, разбор своего кадра 0,4, сжатие в одну строку 0,3 |
| плееру на кадр | 1,1 мс: разбор 0,4, вложение 0,3, свой кадр 0,4 (плюс рисование) |
| событие → кадр обратно, события подряд | 1,85 мс (в одном процессе — 1,4 мс) |
| анимация приближения через трубу | ~55 кадров в секунду, 6–7 МБ/с |

Локально это почти ничего не стоит. Для сети ~125 КБ на каждое наведение — слишком много. Поэтому удалённое окно будет передавать экран и изменения данных, а не кадры.
