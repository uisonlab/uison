# События как JSON

[English](../../screens/events.md) · **Русский**

Кадры выходят из программы в виде JSON, и события тоже могут приходить в виде JSON. Внутри программы события остаются типизированными: обработчик на Rust получает `cx.key`, а не строку, которую нужно разбирать. JSON-форма нужна там, где событие пересекает границу: на низком уровне C (`uison_app.on_event`), в сообщениях экрану снаружи и в сценариях проверки. Форма одна для всех языков, а общий тестовый файл [`scenarios/events.jsonl`](../../../scenarios/events.jsonl) следит, чтобы Rust и C++ понимали её одинаково.

## Сырые события

То, что сообщает платформа: мышь, палец, клавиши, окно. Программа на C на низком уровне получает их в `on_event` ([урок 9 по C](../c/lessons/09-frame.md), [урок 10 по C++](../cpp/lessons/10-frame.md)).

```js
{"type":"down","x":120,"y":48.5,"button":"left"}   // button: left, right, other, touch (палец)
{"type":"up","x":120,"y":48.5,"button":"left"}
{"type":"move","x":121,"y":49}
{"type":"leave"}                                   // указатель ушёл из окна
{"type":"scroll","x":300,"y":200,"dx":0,"dy":-40}
{"type":"key","code":"char","text":"ж","shift":false,"ctrl":false,"alt":false,"cmd":true}
{"type":"resize","w":1280,"h":800}
{"type":"safe-area","top":47,"right":0,"bottom":34,"left":0}
{"type":"appearance","dark":true}
{"type":"paste","text":"из буфера обмена"}
{"type":"tick"}  {"type":"image"}  {"type":"wake"}
```

- Координаты — в точках от левого верхнего угла окна, с точностью до 1/1000 точки.
- `code`: `char` (набранный текст — в `text`), `enter`, `backspace`, `delete`, `tab`, `escape`, `left`, `right`, `up`, `down`, `home`, `end`, `pageup`, `pagedown`, `back` (Android), `menu`, `f10`. У остальных клавиш `text` — `null`.
- `cmd` — главный модификатор: ⌘ на Apple, Ctrl на остальных системах.
- Незнакомые ключи при чтении пропускаются, отсутствующий модификатор считается `false`.

## Сообщения экрану

Уровнем выше сырых событий. Сообщение говорит не о том, где нажали мышь, а о том, какое действие сработало и что изменилось в данных:

```js
{"action":"save","event":"click","key":"ok","pos":[12,8.5],"clicks":2}
{"data":{"form.query":"jpg","form.agree":true}}
```

- **`action`** запускает обработчик так, как если бы событие пришло от элемента с этим `key`. Обработчик видит те же `cx.event`, `cx.key`, `cx.pos` (относительно узла) и `cx.clicks`. Обязателен только `action`: `event` по умолчанию — `click`, `key` — пустой, `clicks` — 1, без `pos` позиции нет.
- **`data`** ставит значения по путям — так же, как это сделали бы поле ввода, переключатель или ползунок. Производные данные (`derive`) пересчитываются, экран перерисовывается.

Как отправить:

| язык | вызов |
|---|---|
| Rust | `ui.apply(r#"{"action":"save","key":"ok"}"#)` |
| C | `uison_ui_apply(ui, UISON_JSON({"data":{"form.query":"jpg"}}))` |
| C++ | `ui.apply(R"({"action":"save","key":"ok"})")` |

Вызов возвращает `false`, если экран такое сообщение не понимает: JSON с ошибкой или нет ни `action`, ни `data`. Внутри программы сообщение идёт как обычное событие (`Event::Message` в Rust), поэтому его может отправить и сценарий.

## В сценариях проверки

Сценарий (`UISON_SCRIPT`) может отправлять оба вида как есть, рядом с шагами, которые находят элементы по id:

```js
[
  ["tap", "draft/1/0"], ["type", "Buy milk"],
  ["event", {"type":"key","code":"enter"}],
  ["action", {"action":"remove","key":"del-1"}],
  ["action", {"data":{"filter":"done"}}],
  ["capture", "01_done"], ["done"]
]
```
