# Lesson 11. C++17 and JSON

```cpp
// Lesson 11 (C++17): a screen without C++20 widgets, as a uison::Node method chain; a custom component as a JSON string.
#include <string>

#include <uison.hpp>

// A custom component in the same JSON as in a components.json file (R"json(…)json": JSON may contain `)"`).
static const char* COMPONENTS = R"json({
  Note: {
    params: { text: "" },
    body: { Box: { padding: [8, 12], radius: 8, fill: "$theme.card", stroke: "$theme.divider", width: 1,
                   child: { Text: { text: "$text" } } } },
  },
})json";

int main() {
    // One lambda both for the button and for Enter in the field.
    auto add = [](uison::Cx& cx) {
        auto d = cx.data();
        if (d.str("draft").empty()) return;
        d.push("notes", d.get<std::string>("draft"));
        d.set("draft", "");
    };
    auto screen = uison::column().padding(20).gap(12).cross("stretch").children({
        uison::text("Notes").size(22).bold(),
        uison::row().gap(8).children({
            uison::text_field().bind("draft").placeholder("What to remember?").flex().key("draft").on_submit(add),
            uison::button("Add").icon("plus").key("add").disabled("!@draft").on_click(add),
        }),
        uison::for_each("notes", "n", uison::node("Note").prop("text", "@n")),
        uison::text("Total: {@count}").color("$theme.muted"),
    });
    // The rest of the screen settings as {key, value} pairs (in C++20, the uison::Screen struct).
    uison::Ui ui(screen, {{"size", uison::arr{420, 380}}, {"data", uison::obj{{"draft", ""}, {"notes", uison::arr{"Buy bread"}}}}});
    ui.components(COMPONENTS);
    ui.derive([](uison::Data& d) { d.set("count", d.len("notes")); });
    return ui.run("Lesson 11 — C++17");
}
```

## How it works

1. **Method chains.** `uison::column().gap(12).children({…})` is the same tree as with widgets, but without designated initializers: it works in C++17. The methods belong to a single class `Node` (`.prop("anything", value)` — for properties that have no method), lambdas go into `.on_click(…)`.
2. **A screen as a JSON string** — `uison::Ui ui(R"json({ … })json")`: the shortest form, but errors show up only at run time (with their location). The `json` delimiter in `R"json(` is needed: `)"` occurs in JSON.
3. **A screen as a file** — `uison::Ui::load("screen.json")`: you can edit it without rebuilding, and with `UISON_RELOAD=folder` — right in the running program.
4. **The rest of the screen settings** in C++17 — as pairs `{{"size", uison::arr{420, 380}}, {"data", uison::obj{…}}}` (in C++20 — the `uison::Screen` struct).

## Which to use when

| | widgets (C++20) | chain (C++17) | JSON string | file |
|---|---|---|---|---|
| property names checked by | the compiler | at run time | at run time | at run time |
| IDE hints | all fields with descriptions | common methods | none | JSON editor |
| lambdas on elements | yes | yes | no (by name) | no (by name) |
| edit without rebuilding | no | no | no | yes, `UISON_RELOAD` |
| shared with C and Rust | no | no | yes | yes |

You can mix them: the screen as widgets, a custom element as JSON (as here), a large reference screen as a file.
